この文書は、Macを優先してこのリポジトリを運用可能な状態へ整えるための責務と完了条件の正本です。
2026-09-08のユーザー指示に基づきます。実装仕様は[設計書](DESIGN.md)、
現在の実測結果は[検証記録](operations/collection-recovery-verification.md)を参照します。
過去の日付付き計画は履歴として保持し、現在の優先順位は本書に集約します。

## ゴールと「適切な状態」

承認されたMacの議論運用で、依頼の固定、正しい席への受渡し、回答の検証と一度だけの回収、
元担当への返却、実処理の確認までを再現できる状態を目指します。
コードが動くこと、通常CLIへ導入されていること、実際の席で往復したことは別々に確認します。
常設の自動再開とClaude Desktop Code指定席は、未確認のまま完了条件から外しません。

| 完了条件 | 判定に使う証拠 | 未達時の修復 |
|---|---|---|
| 採用する変更が正式mainに統合され、重大なレビュー指摘が残らない | 対象PR・SHA・レビュー解決状態・必要なCI | 原因を修復し同じ範囲で再検証 |
| 通常CLIが正式版を使い、一時worktreeへ依存しない | 固定wheelのhash、導入先とmainの比較、repo外CLI smoke | 正式ソースから再構築・導入し照合 |
| MacのCMUX経路で依頼から回答回収まで再現できる | 正式wrapper、席ID、invocation、回答・議事録hash、再回収結果 | 搬送・回答・回収の失敗段階を切り分け修復 |
| 回答が元担当へ返り、実処理まで確認できる | 固定した送り先・通知hash、native receipt、担当結果の再読 | 不明な送信を再送せず実結果を照合 |
| 常設自動再開が対象を限定して動く | 承認済みROOT/topic・返却先・頻度・終了条件、正式定期実行設定と実行結果 | 既存の正式起動機構へ接続し、無人起動を別途実測 |
| Claude Desktop Code指定席で1依頼1回答を確認できる | 指定席「AI Round Table 完成」の受理、回答保存、検証・回収結果 | UI接続障害を解消して指定席で再検証 |
| 作業場所と文書が整理され、他担当の作業を失わない | 正本checkoutのclean、owned branch/worktree一覧、保全と回復可能性 | 包含・所有・保全を確認して不要な自分の作業場所だけ整理 |

すべての必須条件に証拠がそろった時に全体完了とします。外部接続や人間判断が残る場合は、
対象・理由・担当・次の行動を明記して未完了を維持します。未知の環境での無故障までは保証しません。

| 各AI・サブエージェント | 指定された独立範囲の実装・レビュー・回答と証拠 | 主担当へ結果・残務を返す。送信成功だけで完了にしない |

## 次に進む順序

1. **基準を固定する**：本書とREADMEの入口を整え、現行の検証記録との矛盾をなくす。
2. **残るレビュー修復を採用する**：PR #21を現行mainと統合して検証し、正式反映後に通常CLIを更新する。
3. **運用経路を閉じる**：既存のCMUX往復証拠を維持し、常設起動の対象を確定して正式機構へ接続する。
   Claude Desktop指定席の接続障害は独立して解消し、実席の回答回収まで確認する。
4. **整理と最終照合**：自分の採用済みbranch/worktreeを保全後に整理し、main・通常CLI・文書を照合する。
   全体完了条件を一行ずつ実証し、未達があれば該当手順へ戻る。

本書の計画項目を終えたという自己申告で状態を更新せず、検証記録に証拠を残します。

## 小さなPDCAと失敗の先読み

一周は「一つの不具合または接続境界」に限定します。
着手前に対象・担当・受入条件と、次に壊れそうな点を一つ置きます。
変更後に必要な試験と独立レビューを行い、正式反映・導入・実測の順で確認します。
その結果で検証記録を更新し、次の一周を選びます。変化がない同じ試験の反復はしません。

優先して観測する失敗は、誤送信・送達不明、遅着と重複回収、正式ソースと導入版のずれ、
担当が止まったままの返却、削除による他担当作業の消失です。
既存のID/hash検証・journal・claim/receipt・Git履歴を使い、新しいqueueやschedulerを重ねません。
公開契約や責務を変更する場合だけADRに理由と代替案を残します。
