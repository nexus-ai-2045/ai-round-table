# ADR-0003 Mac優先運用と正本の境界

- 状態：採用済み方針の文書への反映
- 日付：2026-09-08
- 根拠：ユーザーのMac優先・Claude Desktop Code指定席・全実装GOと、責務・ゴールの明文化指示

## 背景

旧設計書のWindows限定・CC製品名での席除外・製品repo内の固定rootという記述が、
採用済みMac実装、READMEの役割分離、指定ROOTを使うCLI契約と食い違っていた。
現在の計画も過去の版別計画と区別する必要があった。

## 決定

Macを優先し、既存Windows経路を維持する。CMUX制御はProjectsの正式wrapperを使い、
製品のpacket・回答回収契約に薄く接続する。製品独自のschedulerは追加しない。

議論のホスト自身は独立した参加席を兼ねない。Claude Desktop Codeの別指定席は
ユーザー指定の検証対象とする。製品実装の採否責任はADR-0002のintegration ownerが持ち、
議論の裁定はユーザーに残す。

議題データは指定ROOTのminutes/<topic>/配下に一つだけ置き、Git管理を必須とする。
製品repo内という固定位置は要件にしない。既存データの移動や実運用ROOTの選定を
この文書だけで実行済みとせず、既存journalを照合して対象を固定する。

現在の責務・到達条件・順序はROADMAP、実績は検証記録、実行契約はPROTOCOLを正本とする。
過去の計画・判断表は履歴として残す。

## 不変条件・検知・修復・証拠

- 不変条件：一つの議題に複数の正本を作らず、送達・回収・担当の実作業・常設起動を別に判定する。
- 検知：既存のGit管理検査、invocationとhash、followup claim/receipt、導入版照合を使う。
- 修復：違反した責務の担当が既存の入口を修復し、同じ対象で検証する。失敗を別のqueueで覆わない。
- 証拠：collection-recovery-verification.mdの状態表と対象PR・実測への参照を使う。

代替案の製品名による一律除外、製品repo内だけへの保存、新しい常駐daemonは採用しない。
新機能やデータ移行を伴わず、既存の実装・承認範囲へ文書を合わせる。
